# 论文主线的一次固定确认

冻结日期：2026-11-14；冻结发生在本轮首次模型调用和答案评分之前。质量路线，不在结果出来后转成效率路线。已有开发竞争力筛选与后处理设计实验保持原结论。

## 研究问题与主比较

保留旧完整 `quote_anchor` 为唯一完整主候选；主比较为 `quote_anchor − direct+rank_add`，512 个 Qwen token 预算，Qwen3.5-9B 读者。AP3、完整原文句上的强重排同时报告。不得把句子化的 retain_fill 诊断替换成完整主候选，也不把完整系统差异归因于 role 提示。

主检验是 **Hotpot 上差值至少 +2 F1，来源配对双侧 95% 区间下界 >0**。MuSiQue 和 Phi 是预先指定的迁移验证。它们不能替代未通过的主检验。全部指定迁移比较须为正且区间下界 >0，才支持跨数据/读者的正向结论。单项次要区间为描述性；合取门槛要求全部通过，不按显著项挑选。

## 固定样本与可解释范围

- Hotpot：从已有全训练/验证来源连通图中未使用的 4,002 个合格分量中，按固定哈希选 1,400 个，每分量一题。原 evaluation480、natural192、已分配训练/校准集均排除。该图已排除与 MuSiQue 训练/验证支持内容的双向重叠。项目内来源留出不等于基础模型训练时绝对未见。
- MuSiQue：所有旧开发集、训练/校准及保留样本的原子子问题均排除。剩余 2,209 题构成 535 个原子连通分量，每分量按固定哈希取一题，共 535 题。没有按答案、输赢或语义链质量筛题。组成是 491 道两跳、41 道三跳、3 道四跳，目标总体是这种分量抽样后的题目分布，不是官方数据集原始频率。
- MuSiQue 是新题/新原子子问题验证，**不是事实全新验证**。严格事实隔离只有 82 个可用样本、全两跳，不能承担大规模确认。因此在看到新结果之前明确调整该数据的检验范围；不改称“独立事实泛化”。选中的 535 题按完整支持段文本合并为 520 个分量，最大分量 3 题，主要报告这些分量的聚类区间。事实近义重复仍可能漏检，旧语料事实重合不因聚类而消失。
- MuSiQue 训练数据有一题原生 16 个候选段落，其他为 17–20 个；原样保留，不填充、不丢题。公开接口只输出问题、原文段落及位置，不输出支持标记、答案或分解。原始 JSON 隔离检查解析过行对象，但答案值不用于分配，也不导出到推理输入。
- 所有 ID、来源哈希与诊断子集固定在 allocation.json；不在不显著后加样、不修改预算、不增加提示版本。

## 功效与停止规则

旧 48 题面板主比较的配对标准差：Hotpot 26.19、MuSiQue 42.84 分。正态近似下，Hotpot 1,400 题对真实 +2 分相对 0 的双侧显著性检验约有 81.5% 功效。MuSiQue 535 题的对应功效只有约 19.1%，80% 可检测效应约 5.19 分，不能把未显著解读成排除了 +2。旧小样本方差、文档相关性与新抽样分布均带来不确定性；这些数字不是达到“点估计≥2 且显著”的联合概率。

若完整系统主门槛、全部指定迁移或设计门槛未通过，本轮不认定当前“质量提升＋可迁移机制”论文论据成立，不扩样、不调提示再刷此面板。保留所有结果再决定是否能写更窄的结论；不能自动宣布方法不存在或不能投稿。即使全部通过，也需成本、基线实现和完整案例复核后才能判定投稿就绪。

## 固定材料、读者与后处理诊断

完整矩阵：1,935 题 × 4 方法 × 2 读者 = 15,480 个逻辑条件。提案固定为旧 role 版本与当前 direct 版本：role 至多一次机械格式修复、direct 一次，均最多输出 2,048 token；共至多 5,805 个提案调用。固定旧 Beam 检查点、原 FP32 头输出的 Qwen3-Reranker-4B 分数、旧预算和回退规则。无训练、无合成问句。

保留既有候选粒度：Hotpot 的 rank_add 使用原始 context.sentences 原生句及原始空白位置；MuSiQue 沿用既有句子切分。两者均不读取支持标记。后处理机制诊断在两数据上统一使用各自 source.spans 的完整句，不能混淆这两套候选单位。

Qwen 生成的同一证据字符串原样交给 Phi-4-mini-instruct，明确这是证据迁移。所有方法仍是 Qwen 512 token 下生成的系统；分别记录实际 Phi 证据与完整输入长度，**不宣称 Phi 逐题等长或 Phi 原生 512 token 实验**。Qwen/Phi 都采用 BF16、SDPA、贪心解码；Hotpot 原回答协议最多 128 输出，MuSiQue 原 JSON 协议最多 2,048 输出。停止/截断与格式失败全报。Hotpot 按旧官方 EM/F1 原文评分；MuSiQue 未正常停止或解析失败计 0，使用原官方别名最大值评分。

诊断子集由两个数据集各自的固定哈希取 256 题，共 512 题；两种提案、四种后处理、Qwen 读者 = 4,096 条件。直接调用已冻结的 proposal_retention_v1：完整原文句、相同候选池与渲染，retain_fill、greedy、knapsack、knapsack_matched。全部 1,024 主要对必须证据 token 与完整输入 token 精确相等；否则停止技术验收，不以“近似均值”代替。

诊断的四组主要差值需下界 >0，role 两数据各 ≥+2，direct 两数据各 >0；对完整预算 greedy/knapsack 的点估计均不得低于 −1。所有四组都报，稀疏效应不事后删组。该子集是固定资源上限的确认，未声称已精确达到机制检验 80% 功效。没有新重排器或新特征，也不把保留句子叫作认证完整链。

## 评分、成本与运行

总计 19,576 个逻辑读者条件；同模型、同消息、同输出上限的请求精确去重。提案、排序与检索中间产物共用，但每方法的假想部署账单计入所需步骤，不能把共用计算当作免费。记录读者输入/输出、提案输入/输出/修复、重排器输入/前向、检索器实际 token/前向、CPU 装包时间与每阶段资源。不同模型 token 不折算成一个虚假的总算力单位。共享 GPU 上的时间只作描述，不作控制充分的速度结论。

每个数据集/读者/方法的 EM/F1、实际长度和失败率全报。置信区间用固定种子 30、10,000 次来源/支持文档分量 bootstrap；同一分量内整组重采样，并按题目加权。跳数分层单列，3 条四跳不能支持四跳能力主张。

完成全部读者矩阵、检查身份与长度后才读取本轮参考答案并评分，不中途看分数。Hotpot 答案仅通过已选 ID 过滤导出；不打开受保护面板文件。

CPU 预载后等待 GPU；检索、重排、提案、装包、两读者分阶段执行。9B 为全 GPU BF16，不量化、不卸载，空闲达到 26,000 MiB 时申请容量；排队与总运行均无过期时间，已完成结果不重算。明确 OOM 可重排队；未知中断/算法错误保留现场并停止，不能自动吞掉失败。不会终止其他用户进程。

本轮输出是对既定投稿路线的确认与止损依据，不预写成功摘要，不自动追加下一轮。
