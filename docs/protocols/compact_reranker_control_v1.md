# 全候选紧凑重排序对照：推理前固定方案

2026-11-16。用户已授权执行。目的：检验 JQR 相对紧预算 C 的巨大差值是否依赖 C 的候选池与混合片段构造，并核查 C 的具体选材失败模式。

## 范围与对照

沿用已暴露的 HotpotQA-1400、MuSiQue-535 面板与 Qwen3.5-9B、Phi-4-mini-instruct 两个读者。本轮是补充策略比较，不是独立复现，不改变此前主要检验或句级等长诊断的判定。

只新增 E_full_pool_tight 一臂。A_jqr 原样复用。E 使用全部原始可用段落中的完整句子及既有 Qwen3-Reranker-4B 逐句分数，调用未修改的生产 `relation_preserving_pilot_v1.pack(..., 'recomp_sentence', ...)`。分数降序、原句位置打破平局；每次合并原文区间并重新计数，整句放不下则跳过，不截断、不添加填充文字、不重新生成引文、不训练、不调分数或装包规则。

每题 E 的 Qwen token 上限等于同题 A 的实际证据长度，名义外层上限仍为 512。完整 512-token 下必须逐题复现存档 strong_rerank 材料。原 A 准入题的既有 anchor 必须自然保留：该 anchor 是完整预算下第一个可接受的句子，且 A 的材料包含它。检查这一性质但不改变生产选材逻辑。E 在全部 1,935 题上独立装包，不按 JQR 是否回退选择分支、不读取提议引文来优化自身；所有回退题仍在总体分母。原 A 回退时不强行把 E 改成 A。

本对照开放全部句子候选，相比旧 C 同时改变候选范围和候选粒度，因此是紧凑选材策略比较，不声称单独隔离纯保留机制。预算依赖 A，估计的是在 A 所用额度内的选材表现，而非独立预算扫描或不依赖 A 的完整部署策略。相同上限不等于相同实际长度；必须同时报告长度差、精确匹配比例、P50/P90/最大缺口与读者完整输入长度。

## CPU 审计与冻结

新推理前冻结本文件、实现、测试、依赖身份及原材料哈希。选材阶段不读取新臂参考答案或得分。缓存复用仅核验请求、历史模型/解码配置与输出身份，不以答案好坏决定是否复用。

逐题重建旧 C 并核对材料哈希；记录每个候选的接受/已覆盖/超限决策和 token 增量。按原文包含关系统计引文损失；统计完整句、部分句、渲染区间数量，不将其等同于语义完整性。

检验“长句挤占”的构造见证：若把 C 接受的一条完整句替换为其中已提议的短引文，能在保住原先已保留引文的同时放入一条遗漏引文，则记录实际区间和 token 数。此处使用提议内容仅作诊断，不影响 E 的构造；见证不证明句内其他内容无用，也不是可部署补救方案。没有见证不等于不存在其他挤占模式。

冻结所有 E 材料、全部请求和复用映射后才开始新增 QA。A、旧 C/D、原 full-budget reranker 的已有回答仅在完整请求、模型、输出上限、prompt token 与实验身份一致时复用。读者使用既有 BF16、SDPA、全 GPU、greedy、thinking=False，保持原输出上限（Hotpot 128，MuSiQue 2048）。总逻辑条件为 1,935 × 2 臂 × 2 读者 = 7,740，新增调用最多 3,870。

## 统计与结论规则

完整矩阵完成后一次性评分，保留全部输出失败和构造失败。四个数据集×读者条件全部报告 F1、EM、配对差值及来源组件聚类 bootstrap 95% 区间（沿用种子 30、10,000 次）。同时展示原 C 的固定成绩及 E−C 描述性差值，帮助判断旧对照敏感性。

焦点比较为 MuSiQue/Qwen 的 A−E，因为本轮针对该组 A−C=28.27 的解释问题。预先使用 +2 F1 且 95% 下界 >0 作为具有实际意义的优势标准；它不替代旧研究的 primary。其他三组完整报告，不能挑有利者作为唯一结论。全四组均达到该标准才称四设置稳健优势；否则按实际通过范围描述。区间跨零不是等价；未达到门槛不意味着系统无效。不能把任何 A−E 差值写成精确等长下的纯保留效应。

若焦点优势未获支持，收缩对强紧凑重选的主张，原 A−C 仍只作为特定构造的诊断。若 E 追平/超过 A，明确记录，不增加新变体或扩样寻优。若长度缺口明显，报告其限制，不以填充、截断或挑选题目制造等长。所有统计均为已暴露面板上的补充证据。

## 运行

复用冻结缓存，不新增 proposer 或 reranker 调用。Phi 先运行，之后 Qwen；GPU 不足持续排队，无等待或运行到期时间。Phi 入场 12,000 MiB；Qwen 沿用先前已通过精确输出回放的全 GPU BF16 20,250 MiB 入场策略，内存预留/上限 19,000/19,500 MiB。出现明确 OOM 后切回 26,000/24,000/24,500 MiB 并继续排队，不改变模型、精度、注意力实现或解码。共享 GPU 入场锁继续使用，不终止其他进程。未知推理中断保留现场并停止，不静默重试。
